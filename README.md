# Sidecar Design Pattern – Spring Boot Microservices

A practical implementation of the **Sidecar Design Pattern** using Spring Boot. This project demonstrates how a separate sidecar service can provide supporting functionality to a primary application without tightly coupling that functionality with the business service.

## Architecture Overview

The project consists of two independent Spring Boot applications:

1. **Book Service (Main Application):** Responsible for the primary business functionality and generating application logs.
2. **Logging Service (Sidecar):** Runs alongside the main application and independently reads and processes the logs generated by the Book Service.

Both services communicate through a shared file mounted into their respective environments.

## How It Works

1. The Book Service executes its primary business operations.
2. Application logs are written to a shared file (`/shared/app.log`).
3. The Logging Service runs independently alongside the Book Service.
4. The Logging Service accesses the same shared file.
5. It reads the application logs without requiring the Book Service to implement log-processing functionality.

This approach separates supporting functionality from the primary business application.

## Running the Project Locally

### 1. Clone the Repository

```bash
git clone https://github.com/YOUR_USERNAME/sidecar-design.git
cd sidecar-design
```

### 2. Build the Applications

Build both Spring Boot applications using Maven Wrapper.

Windows:

```powershell
cd book-service
.\mvnw.cmd clean package -DskipTests
cd ..

cd logging-service
.\mvnw.cmd clean package -DskipTests
cd ..
```

Linux/macOS:

```bash
cd book-service
./mvnw clean package -DskipTests
cd ..

cd logging-service
./mvnw clean package -DskipTests
cd ..
```

### 3. Run Using Docker Compose

From the project root:

```bash
docker compose up -d --build
```

Check running containers:

```bash
docker compose ps
```

View logs:

```bash
docker compose logs -f
```

Stop the containers:

```bash
docker compose down
```

## Running with Kubernetes

The Sidecar Design Pattern can also be implemented using Kubernetes Pods.

In Kubernetes, the Book Service and Logging Service run as separate containers inside the same Pod.

Both containers share a volume mounted at `/shared`.

An `emptyDir` volume can be used to provide shared storage between containers within the Pod.

Apply the Kubernetes configuration:

```bash
kubectl apply -f sidecar-deployment.yaml
```

Check the Pod:

```bash
kubectl get pods
```

View Book Service logs:

```bash
kubectl logs <pod-name> -c book-service
```

View Logging Service logs:

```bash
kubectl logs <pod-name> -c logging-service
```

## Benefits of the Sidecar Pattern

- **Separation of Concerns:** Supporting functionality remains separate from business logic.
- **Independent Deployment:** Supporting components can be developed and maintained independently.
- **Reusability:** Similar sidecar functionality can be reused across multiple applications.
- **Technology Flexibility:** The main application and sidecar can use different technologies.
- **Maintainability:** Changes to supporting functionality do not necessarily require changes to the main application.

## Conclusion

This project demonstrates how the Sidecar Design Pattern can separate cross-cutting concerns such as logging from the primary business application.

By running the Book Service and Logging Service alongside each other and sharing a common file, the implementation illustrates how supporting functionality can be independently maintained without adding unnecessary complexity to the main application.
